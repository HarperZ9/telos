Title:

```text
The Next Agent UX Primitive: Show Me the Receipt
```

Body:

```text
The next useful agent interface is not a bigger chat box. It is a receipt viewer.

When an AI workflow matters, the final answer is only one artifact. The route matters too. What context did the model see? Which tools were visible? Which tool calls happened? What changed on disk or on a remote service? Which checks passed? Which assumptions were never verified?

That is the layer I am building toward with Project Telos.

The point is not to make every agent slower or more bureaucratic. The point is to make ambitious work easier to trust, debug, hand off, and improve. If a model helps with source intake, codebase navigation, research synthesis, creative exports, math demos, or external actions, the workflow should leave a compact record that another person can inspect tomorrow.

A useful receipt does not need to be fancy. It needs to answer concrete questions:

What source material was admitted?
What context envelope was selected?
What tool surface was exposed?
What action was attempted?
What evidence supports the result?
What failed, drifted, or stayed unverifiable?

Those questions change agent UX. They move the interface away from pure conversation and toward inspectable operations. A reviewer should be able to say: show me the route, show me the tools, show me the artifact, show me the verdict.

This is also why I think adoption should be driven by ambition, not only risk reduction. Receipts are not the product by themselves. They are the operating discipline that lets people do more with the product: bigger codebase handoffs, better research packets, stronger creative systems, reproducible demos, and safer tool use.

Project Telos is an open public workspace for that direction: Gather for source intake, Index for workspace structure, Forum for routing, Crucible for verification pressure, and Telos as the shared room tying the pieces together through local CLI/MCP surfaces.

The current public repo is here:

https://github.com/HarperZ9/telos

I am looking for testers with real workflows where a model answer is not enough. Bring the task that currently feels hard to inspect. The best feedback is a missing receipt field: the source ref, replay handle, measurement, policy result, or verifier that would make the work easier to trust later.
```
